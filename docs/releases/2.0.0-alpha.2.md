# SecureMCP 2.0.0-alpha.2 preparation

Status: a [verified candidate is frozen for independent trials](../validation/ALPHA2.md). Human acceptance and npm publication remain pending. These supplemental notes do not rebuild or replace the tarball. Follow [the execution plan](https://github.com/perfecxion-ai/secure-mcp/issues/57) for completed work and remaining gates.

Alpha.1 remains available on GitHub with its original tag and assets. The maintainer rejected promoting that tarball to npm. Its historical evidence remains attached to that artifact and does not automatically validate alpha.2.

The merged consumer-facing changes enforce Node >=24.22.1 <25 at startup, provide installed-package instructions and complete core documentation, test the same tarball bytes that CI uploads and attests, and retain a fresh consumer lockfile with dependency comparison. A reproducible alert-triage example and public trusted-tool guide now ship with the package.

The corrected production SBOM includes runtime dependencies omitted by the previous npm omit selector. Historical alpha.1 assets remain unchanged; see the [correction record](../validation/2026-11-03-sbom-inventory-correction.json). A dependency comparison also caught newer Hono transitive patches in fresh installs; the reviewed lockfile now matches those versions. Engineering checks do not substitute for final exact-artifact or independent usage evidence.

The candidate record binds the source commit, successful CI run, tarball digest, freshly verified provenance/SBOM, fresh x64/ARM64 consumer lockfiles and matching dependency graphs. A successful registry read confirmed this version is unused; recheck before any approval and publication. Collect exact-digest VS Code and Cursor trials with restart and repeat useful work. Retain independent remote-operator evidence while remote authentication remains a principal launch claim.

The npm decision is separate and applies to one exact artifact. Keep `latest=1.0.0`, publish only to `alpha` if separately approved, and use exact consumer pins with retained lockfiles. Keeping the v1 tag unchanged protects compatibility; it does not endorse v1's security. See [migration guidance](../MIGRATION.md) for incompatible APIs, transports, identity behavior, Linux support and the AGPL-3.0-or-later license declaration.

This alpha remains a runtime for trusted handlers and trusted workspaces. It does not sandbox plugins, authorize individual documents through tool scopes, guarantee immediate JWT revocation, provide a complete audit-retention service, or prevent prompt injection within granted authority. See [the threat model](../THREAT_MODEL.md).
