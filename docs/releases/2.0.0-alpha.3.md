This version is reserved for the fixes identified by the November 3 review. No frozen candidate, independent acceptance or publication is claimed. See the [remediation plan](../validation/2026-11-03-review-followup.md) and [tracker](https://github.com/perfecxion-ai/secure-mcp/issues/57).

Alpha.2's retained package and evidence remain unchanged. Its availability findings must be resolved before the successor is handed off for acceptance. Package changes require new candidate evidence; neither alpha.1 nor alpha.2 approval transfers to alpha.3.

## Runtime changes

- Durable audit delivery reuses a bounded Unix stream. The matching collector batches bounded journal writes and acknowledges each record only after `fsync`. Loss with outstanding records fails closed without retrying ambiguous writes. Runtime shutdown drains and closes its owned sink; custom close hooks have a bounded timeout and retain failure state.
- HTTP validates request targets, Host and Origin before token verification, and verifies protected headers before buffering request bodies. Token verification and authenticated admission have separate budgets. Admission reserves three pending audit slots per request and ordinary overload returns 503 without latching a healthy audit sink. Connection and partial-header limits still require proxy controls.
- HTTP accepts one validated origin-form routing target and rejects malformed or normalized alternatives before SDK dispatch. JSON-RPC batches are rejected before they can fan out beyond request admission.
- HTTP connection headers preserve Node's 1,000-request retirement signal in both protocols. A five-second advertised idle timeout permits reuse with the built-in client's retirement margin. This fixes repeated 503 responses discovered during the follow-up endurance run without removing finite socket limits.
- Tool arguments with an own `__proto__` key are rejected before the SDK can silently rewrite them; nested occurrences and direct library calls are also checked before custom schema validation. This does not establish a prototype-pollution exploit, and schemas can still deliberately declare `constructor` or `prototype` fields.
- JWT access-token types accept `at+jwt` and `application/at+jwt`, case-insensitively. Whitespace, parameters, missing/unrelated types and failures of signature, issuer, audience or lifetime checks remain rejected.
- CLI startup reports sanitized field names and fixed reasons for configuration, filesystem, argument and listener failures. Unsupported Node versions still fail before dependency loading. Stdout remains reserved for MCP outside explicit doctor output.
- Audit correlation uses server-generated request IDs, with admission distinguished from terminal results. An acknowledged runtime rejection is not duplicated as another protocol rejection. Failed acknowledgement preserves the generic unavailable fallback. Unhealthy audit makes CLI EOF/signal shutdown fail even when no tool remains active.

## Operational changes

HTTP needs `audit.maxPending >= 3`; admitted requests are capped at `min(2 * limits.maxConcurrent, floor(audit.maxPending / 3))`. Admission remains occupied until scoped audit work and terminal delivery settle. Pre-admission HTTP rejections use aggregate counters rather than durable individual records. Successful health, metadata and CORS preflight responses are also outside the per-request audit stream. Operators needing rejected-request detail must retain it at the proxy without exposing credentials.

An audit failure before response headers are sent returns HTTP 503. A legacy SSE response already started with HTTP 200 cannot change that status; its MCP result/stream and readiness expose the failure. Count tool terminal outcomes separately from `allowed`, which records admission rather than success. See [operations](../OPERATIONS.md) and [the threat model](../THREAT_MODEL.md) for the complete boundaries.
