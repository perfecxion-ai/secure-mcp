# Durable audit acceptance

Build the package, then run `npm run test:audit`. The lab launches the included Unix-socket collector as a separate process in a private temporary directory. It verifies 400 concurrent-batch calls, kills the collector after acknowledgement, checks every record, restarts and appends, exercises a full journal limit, and blocks delivery during a 200-call burst. It removes its fixtures on exit. An optional argument to `verify.mjs` writes the bounded JSON result.

The journal limit probe is an application storage limit, not a simulation of filesystem corruption or a physical full disk. The blocked collector probe tests timeout/backpressure. Neither proves survival of a host power failure. Node 24 on Linux is required. The collector uses a single file writer and fsync before acknowledgement; operator-controlled private directories and monitored retention are required for validation.

Run `node labs/audit/storage-failure.mjs` after building to test actual filesystem exhaustion. This separate Docker lab puts the collector journal on a 64 KiB tmpfs while leaving its application limit at 256 MiB. It fills the filesystem, verifies that an independent write receives `ENOSPC`, and checks that the runtime returns `audit_unavailable` and latches readiness unhealthy. The container has no network, a read-only root, an unprivileged user, and bounded resources. It is removed after the test. CI runs this probe after the container acceptance check.

Persistence checks use the production 1,000 ms audit deadline; the blocked-collector fault probe explicitly lowers it to 200 ms. Using the fault deadline for fsync batches caused a shared-runner CI failure, so these two workloads have separate budgets. CI pins Node 24.22.1 to match the container and local validation runtime instead of accepting an older cached major-version match.
